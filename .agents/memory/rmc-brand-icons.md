# Brand icons are hand-maintained copies, not generated from the logo

The in-app header logo is `rmc-app/src/assets/logo-king.png` (the gold CONCRETE KING
crown + mixer-pin emblem + wordmark). NONE of the other brand surfaces are derived
from it at build time — they are separate static files that must be regenerated by
hand whenever the logo changes:

- Web favicon / PWA: `rmc-app/public/{favicon.png, favicon.svg, apple-touch-icon.png,
  pwa-192.png, pwa-512.png}` (referenced by `index.html` + the VitePWA `manifest.icons`
  / `includeAssets` in `vite.config.ts`).
- Social card: `rmc-app/public/social-preview.png` (og:image / twitter:image).
- Compact mark: `rmc-app/src/assets/logo-ck.png`.
- Android launcher: `rmc-app/android/app/src/main/res/mipmap-*` generated by
  `@capacitor/assets` from `rmc-app/assets/{logo.png, logo-dark.png}` (a crown-only mark).

**Symptom:** "domain shows the OLD logo." Root cause is almost always that `logo-king.png`
was updated but `public/` icons (favicon/PWA) still hold the previous artwork — they were
never regenerated. The favicon/PWA icons keep the same filenames across deploys so
browsers + the Workbox precache cache them hard; a content change bumps the precache
revision, but a hard refresh may still be needed to see the new tab icon.

**How to regenerate** (favicon/PWA from the emblem): use `sharp` (already a direct devDep
of rmc-app — run the script from inside `rmc-app/` so it resolves). Trim `logo-king.png`,
take the top ~63% (crown+pin emblem, drop the wordmark), trim again, then composite
centered on a transparent square at 64/180/192/512. The full 1254² lockup is too tall to
crop with hardcoded pixel coords reliably — trim-first is the robust approach.
